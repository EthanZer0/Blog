## 后续可优化项与取舍

1. **较高优先：拆分文章增强模块。** 当前入口同时引入图片、视频、代码、图库、标签页等渲染器。文章只使用一类内容时也会加载共同模块中其他逻辑。可按内容类型分割异步模块；需要同时处理嵌套 Tabs 和样式加载时序，避免重现此前图片遮罩问题。本轮已先跳过完全不需要增强的文章。
2. **较高优先：中文字体和全局 CSS。** 当前全局 CSS 约 510KB（解压），其中 @font-face 定义约 123KB，中文字体以 Unicode 分片按需下载。不能把磁盘上全部字体文件之和当作首屏下载量。可评估把字体声明独立为缓存文件、分离文章专属样式；固定正文字符子集会影响未来新增文章和搜索文本，不能直接删字体分片。
3. **中等优先：背景绘制预算。** Canvas 桌面持续逐帧绘制，当前后台、手机、减少动态和文章页会停止。降低帧率/密度可省电，但会改变已验收的效果；应先测低端设备再决定。
4. **中等优先：外链 favicon。** 未内置品牌图标的链接会依次探测最多五个 favicon 地址；可按域名共享请求与缓存，并设超时。跨站请求失败本身不代表博客资源缺失。
5. **中等优先：弹层和滚动逻辑的维护。** 原生锚点与 React 目录现在各自使用一套相同弹簧参数；可进一步统一成一个滚动服务。多个组件监听滚动目前多数有卸载清理，不能仅凭多个监听判定泄漏。源码中若干长单行组件影响可维护性，可另做纯格式化整理，格式化本身不会提高运行性能。
6. **内容规模增长：页面数据。** 持久化 ModalRoot 在每页携带公开文稿的标签元数据，首页动态列表携带全部公开条目。当前四篇内容影响很小，未来大量文章时可加载独立索引和限量动态；不能直接裁掉标签功能。
